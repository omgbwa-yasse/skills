# .docx style guide — apply only when the user asks for a Word file

Read `/mnt/skills/public/docx/SKILL.md` first. This guide applies on top of it, unless the user's
organisation imposes its own graphic charter — in which case theirs prevails: ask before generating.

---

## File structure

```
Header block
  → "Decision memo" + full subject line
  → Date, author, addressee (the decision-maker)
  → Classification/confidentiality marking if applicable

Question and context               (3-4 lines)
Recommendation                     (stated up front, one paragraph)
Options compared                   (table)
Evaluation criteria                (table)
Commitment block                   (owner, deadline, consequence of delay)
Appendix                           (only if needed — calculation detail, sources)
```

One to three pages for the body. The appendix can run longer but stays clearly separated.

## Styles

| Element | Value |
|---------|-------|
| Body text | Arial or Calibri 11 pt, line spacing 1.15 |
| Heading 1 | 14 pt bold |
| Recommendation paragraph | Set apart with a shaded box or a left border rule — it must be visually unmissable |
| Table header row | Bold, light grey fill |
| Page footer | Date · version · page number |

## Layout rules

- No cover page for a Standard memo — it's a working document, not a formal report. A Deep memo
  going to a board may take a minimal cover (title, date, addressee) if the organisation's convention
  expects one.
- The recommendation must be visible without scrolling past the first screen/page.
- Keep the options table on a single page; if it doesn't fit, the option set is probably too large
  for a decision memo — reconsider before reformatting to fit.

## File naming

`decision-memo_[abbreviated-subject]_[YYYY-MM-DD].docx`

Example: `decision-memo_vendor-x-migration_2026-08-07.docx`
